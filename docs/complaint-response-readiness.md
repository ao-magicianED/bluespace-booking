# クレーム初期対応体制

作成: 2026-08-29 / 更新: 2026-09-07(鍵の方式・設備トラブルの一次連絡先・清掃体制を反映) / ステータス: 実行フェーズ(運用開始前)
対象: Blue Space 都内7拠点(無人運営) + ブルーストレージ + 民泊
関連: `docs/media-disclosure-strategy.md` 4章・7章・付録C#8(オーナー確認: 未整備・今回整える)

## 0. これを作る理由

`docs/media-disclosure-strategy.md` 4章が参照する2026年5月のスペースマーケット/GoodSpace清掃対応炎上(`docs/competitor-creator-research.md` 6章で出典確認済み)は、実績公開そのものではなく**初動のクレーム対応不備が起点**だった。Blue Spaceは今後、拠点別の予約数・稼働率を継続的に公開する(戦略書1章)。可視性が上がるほど、初動対応の不備がそのまま信用問題化するリスクも上がる。**告知(note/YouTubeの一般公開)を本格展開する前に、最低限のクレーム初期対応フローを明文化し、運用を開始しておく。**

このドキュメントは大企業のCS体制ではなく、**オーナー1人+スタッフ少数で無人運営する7拠点(+民泊+トランクルーム)が実際に回せる最小限のフロー**を目的とする。

**【2026-09-04 確認】一次対応はオーナー(あお)が全件受けている。** スタッフへの委任は現時点で行っていない。したがって本ドキュメントのテンプレートは、まずオーナー自身が使うことを想定する。
**ただしこれは単一障害点でもある** — オーナーが移動中・就寝中・体調不良の場合、一次返信の30分目標が守れない。当面の現実解として、(a)返信できない時間帯があることを前提に一次返信テンプレを定型化しておく、(b)緊急度の高い分類(安全・事故)だけは電話が繋がる導線を確保しておく、の2点で運用する。件数が増えたら6章のとおりスタッフ委任を検討する。

## 1. 想定するクレーム・トラブルの種類

| 分類 | 具体例 | 深刻度の目安 |
|---|---|---|
| 施設・設備の不備 | 清掃不十分、前利用者の忘れ物・ゴミ、空調故障、鍵(テンキー錠)が開かない | 中〜高(GoodSpace炎上と同種) |
| 予約・課金トラブル | 二重予約、キャンセル料・返金を巡る認識齟齬、外部モールとの予約突合ミス | 中 |
| 利用者間トラブル | 前後の利用者との入れ替わり遅延、騒音・近隣クレーム | 中 |
| 安全・法令に関わるもの | 怪我、火災・水漏れ等の事故、盗難 | 高(最優先) |
| SNS上の炎上・拡散 | X等での告発投稿、note/YouTubeのコメント欄での批判 | 内容により中〜高 |
| 物件オーナー(転貸元)からの指摘 | 近隣クレーム、契約条件を理由とした指摘 | 中(戦略書4章と連動) |

## 2. 初動対応フロー(最初の1時間以内にやること)

```
利用者・近隣・物件オーナーからの連絡
  ↓
① 受付(以下いずれかの窓口)
   - 予約確認メール記載の連絡先 / 会員マイページ
   - お問い合わせフォーム(/contact) → 管理者通知(Discord+メール、即時)
   - コンサル問い合わせページ(/consulting)経由の場合も同じ通知経路
   - 外部モール(インスタベース/スペースマーケット/upnow)のメッセージ機能
   - 電話(特定商取引法に基づく表記に基づき請求があれば開示)
  ↓
② 一次受領の返信(受付から30分以内を目標)
   - 「ご連絡ありがとうございます。確認して◯分以内にご連絡します」の一次返信を必ず送る
   - 沈黙が最も炎上を招きやすい(GoodSpace事例の教訓)。事実確認前でも受領の意思表示を最優先する
  ↓
③ 事実確認(受付から1時間以内を目標、無人拠点のため現地確認が必要な場合は前後する)
   - 防犯カメラ映像を確認できる範囲で確認。**テンキー錠のため入退室ログは残らない**(2026-09-07確認)ので、カメラ映像と予約記録が事実確認の根拠になる
   - 該当拠点の直近の予約・清掃記録を確認
  ↓
④ 一次回答(受付当日中、遅くとも翌営業日午前中まで)
   - 3章のテンプレートを使い、謝罪・事実確認結果・当面の対応(返金/割引/清掃手配等)を伝える
  ↓
⑤ 記録(4章のログに必ず残す)
```

**分岐: 保険・弁護士が絡む可能性があるとき(③の時点で判断)**

```
怪我・物損・営業停止が発生した        → 損保ジャパン事故受付 0120-727-110 に連絡
                                        (写真を撮ってから。5-2の補償内容を参照)
相手が強硬・法的措置をほのめかす等
「こじれそう」なとき                  → まずクレームコンシェルに無料相談(弁護士常駐)
                                        ★先に自分で弁護士を探すと保険金が出ない(5-3)
```

## 3. 初動対応テンプレート

### 3-1. 一次受領(事実確認前、即レス用)

> ご連絡いただきありがとうございます。ご不便・ご迷惑をおかけし申し訳ございません。
> 現在状況を確認しております。〇分〜1時間以内を目安に改めてご連絡いたします。

### 3-2. 施設不備(清掃・設備トラブル)への一次回答

> この度はご利用の際にご不便をおかけし、誠に申し訳ございませんでした。
> ご指摘いただいた内容を確認いたしました。[事実確認結果を簡潔に記載]
> つきましては、[返金/一部返金/次回利用割引/清掃手配 等の具体的対応]とさせていただきます。
> 今後同様のことがないよう、[清掃チェック体制の見直し等、具体的な再発防止策]を徹底いたします。

**やってはいけないこと(GoodSpace事例の教訓)**:
- 利用者に清掃対応を依頼した上で、清掃時間分のみの割引に留める、退室後に追加で満額に近い金額を請求する、といった**利用者に負担を転嫁する対応**は行わない。
- 「規約上は〜」等、規約を盾に取ってまず謝罪しない対応は行わない。事実確認前でも、まず不便をおかけしたことへの謝罪を先に伝える。

### 3-3. SNS上での指摘・拡散への対応方針

- 該当の投稿を発見したら、まず**DMまたはリプライで直接連絡**し、公開の場での応酬は避ける。
- 事実関係に誤りがある場合も、公の場での反論・削除依頼を先に行わない。まず個別に連絡し、事実確認・謝罪・対応を先に提示する。
- 独断で判断がつかない場合(法的措置に発展しうる、拡散が大きい等)は、対応を保留してでも先に3章のログに残し、必要に応じて社労士・弁護士等の外部専門家に相談する。

### 3-4. 安全・事故に関わるもの

- 最優先で対応する。必要に応じて救急(119)・警察(110)へ連絡し、その後にBlue Spaceとしての対応を行う。
- **写真・動画で現場を記録する(保険請求に必須)。** 破損物・状況を多角的に撮る。
- **損保ジャパン事故受付 0120-727-110 に連絡する。** ゲストの怪我は施設賠償で1事故1億円まで対象(5-2)。
- 「自社に過失があるか」を現場で判断しようとしない。判断は保険会社が行う。まず記録と連絡を優先する。

## 4. 記録・ログ管理

**すべてのクレーム・トラブルを、`/admin`配下の既存の問い合わせ通知(Discord+メール)とは別に、簡易ログとして残す。** **【2026-09-04決定】Googleスプレッドシートで運用する。`docs/templates/complaint-log-template.csv`をGoogleドライブにアップロード→スプレッドシートとして開けば、そのまま使える(記入例が1行入っているので削除して使う)。** 当面はこの手動運用でよい(3ヶ月運用し、件数・負荷を見てから専用の管理画面の実装を検討する。戦略書5-3章の「まず手動運用してから自動化を判断する」方針と揃える)。

記録する項目:
- 発生日時・拠点
- 連絡経路(フォーム/外部モール/電話/SNS等)
- 分類(1章の6分類のいずれか)
- 事実確認の内容
- 対応内容(返金額・割引・謝罪文送付日等)
- 再発防止策の要否・内容
- クローズ日

**このログは、戦略書6章のKPI「クレーム・炎上0件」の実態把握、および月次のリスク棚卸し(4章)の一次情報として使う。**

### 5-4. テンキー錠・キーボックスの運用(2026-09-07追記)

7拠点すべてがテンキー錠・キーボックス運用のため、**メーカーのサポート窓口という逃げ道が無い。** その代わり、故障の型が限られているので自前の手順で潰せる。

**入れないという連絡の9割は、次の3つのどれか**

| 症状 | 一次切り分け(利用者に聞く/確認する) | 対応 |
|---|---|---|
| 番号を押しても反応しない・ランプが点かない | **電池切れ**。押した時の反応の有無を聞く | 予備電池での交換。現地に行けない場合は下記の緊急手配先 |
| 番号は入るが開かない | **番号違い**(前回分の案内を見ている・入力ミス)。予約IDと案内メールの番号を突合 | 正しい番号を再送。案内の送信履歴を確認 |
| キーボックスのダイヤルが回らない・固い | 経年・凍結・いたずら | 現地対応。頻発する拠点は交換を検討 |

**⚠️ 先に決めておくべき1つ: 夜間に自分が行けないときの手配先**

無人運営でいちばん重い事故は「**利用開始時刻に利用者が入れず、連絡もつかない**」状態。これは返金だけでは収まらず、SNSに書かれる典型パターンでもある(戦略書4章)。現状は「その都度探す」ため、22時に探し始めることになる。

現実的な選択肢は次の3つ。**どれか1つを事前に決めて、上の表の「鍵が開かないときの緊急手配先」に書いておく**だけでよい。

1. **24時間対応の鍵業者を1社決めて番号を控える**(全拠点共通で可)。出張費+作業費で1回1万〜2万円が相場。使わなければ費用は発生しない
2. **拠点近隣の協力者(スタッフ・知人)に、予備キーの保管と駆けつけを依頼**しておく。費用は安いが、確実に繋がるかは人による
3. **予備の入室手段を各拠点に用意する**(番号を分けた予備キーボックスを設置し、平常時は非公開にしておく)。初期費用のみで、夜間の駆けつけ自体が不要になる

> 3が最も安く、無人運営との相性もよい。ただし**予備の番号を配ってしまうと施錠の意味が無くなる**ため、「一次返信で番号を伝え、利用後に番号を変更する」運用とセットで行う。

**あわせて決めておくと事故が減ること**

- **電池交換のサイクルを決める**(例: 清掃時に半年ごと一括交換)。電池切れは「起きてから対応する」より「起きる前に替える」ほうが圧倒的に安い
- **暗証番号を利用ごとに変更しているか**を確認する。固定番号のままだと、過去の利用者が入室できてしまい、盗難・鉢合わせが起きたときに施設側の管理責任を問われる(5-2の保険でも「自社に過失がないケース」は対象外)

## 6. 今後の見直し

- 3ヶ月ごとに、4章のログを棚卸しし、頻発するトラブルがあれば個別の予防策(チェックリスト化、清掃頻度の見直し等)を検討する。
- クレーム件数・対応時間が増え、オーナー1人での初動対応が追いつかなくなった場合は、スタッフへの一次受付委任を検討する(戦略書5-5章の役割分担表と合わせて見直す)。
