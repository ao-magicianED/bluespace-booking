# Google広告コンバージョン計測 セットアップ手順

最終更新: 2026-08-25

## なぜ今まで取れなかったのか

旧直販サイト（UPNOW）では、**予約完了ページが `upnow.jp` ドメイン上にあった**ためです。
コンバージョンタグは完了ページに置く必要がありますが、他社プラットフォームのHTMLに
自分のタグは入れられません。設定の問題ではなく、構造的に不可能でした。

自社サイト（bluespace-booking）は着地から決済完了まで自ドメインで完結するので、これが解消されます。

## この実装の考え方：ブラウザに依存させない

一般的なタグ設置だけだと、次の場面で取りこぼします。

- 広告ブロッカーが入っている
- 決済後すぐタブを閉じられた
- Stripeからの戻りリダイレクトが失敗した

そこで **「Stripeで決済が確定した」というサーバー側の事実**を正本にしました。

```
広告クリック（gclid付きで着地）
   ↓ localStorage に保存（90日・ラストクリック優先）
予約フォーム送信
   ↓ 決済リクエストに同梱
bookings テーブルに記録
   ↓
Stripe Webhook で決済確定
   ↓
確定分だけを Google Ads へ送信（API または CSV）
```

ブラウザで何が起きても、決済が通った予約は必ず記録に残ります。

## 二重計上を防ぐ二段構え

1. 送信対象は `conversion_exported_at` が `null` の予約だけ
2. Google Ads 側も `orderId`（予約ID）で重複排除する

**記録の順序が重要です。** 送信が成功してから `conversion_exported_at` を立てます。
逆にすると送信失敗時に永久欠測になります。

## 手順1：現在の壊れた設定を直す（最優先・APIより先）

現状のコンバージョンは「ページビュー」と「経路検索」で、**購入（予約）は0件**です。
入札戦略が「コンバージョン数の最大化」なので、
**GoogleのAIは経路を調べる人を集めるよう学習しています。**

1. Google広告 → 目標 → コンバージョン → 概要
2. 「ページビュー」「ローカルアクション・経路」を開く
3. **「主要な目標」から「副次的な目標」へ変更**（削除ではなく降格でよい）

これをやらないと、広告費が予約以外の行動に向かい続けます。

## 手順2：コンバージョンアクションを作る

1. 目標 → コンバージョン → **新しいコンバージョンアクション**
2. **「インポート」→「その他のデータソース」→「クリックによるコンバージョンをトラッキング」**
3. 名前：`予約完了（自社サイト）`
4. 目標カテゴリ：**購入**
5. 値：**コンバージョンごとに異なる値を使用**（予約金額を送るため）
6. 計上方法：**毎回**（同じ人が複数回予約したら複数回計上）
7. 作成後、**コンバージョンアクションの数値ID**を控える
   （URLの `ctId=` の数字。環境変数 `GOOGLE_ADS_CONVERSION_ACTION_ID` に入れる）

## 手順3：CSVで運用を開始する（APIの審査を待たずに始められる）

APIの開発者トークンは審査に時間がかかるため、**先にCSVで動かします。**

管理画面 **`/admin/google-ads`** で3ステップです。

1. **読み込む** … 決済確定済みで未送信の予約を取り出す
2. **CSVをダウンロード** → Google広告 → 目標 → コンバージョン → **アップロード** から取り込む
3. **送信済みにする** … 取り込み成功を確認してから押す

⚠️ **手順3を忘れると、次回また同じ予約が出力されます**（Google Ads側の重複排除で
二重計上は防がれますが、毎回同じ行が並ぶので運用が混乱します）。

### なぜ画面から操作するのか

以前は `?mark=1` を付けたURLを開くだけで送信済みにできる作りでしたが、2つの理由でやめました。

- **GETで状態が変わる**と、リンクを踏んだだけ・ブックマークを開いただけで発火しうる
- **マーク時にサーバーがデータを引き直す**ため、ダウンロードしてからアップロードするまでの間に
  確定した予約まで「送信済み」になり、**CSVに入っていない予約が黙って欠測する**

いまは「ダウンロードしたCSVに入っていた予約IDだけ」をPOSTで指定して消し込みます。

**開発者トークンは管理者アカウント（MCC）のAPI Centerでしか発行できません。**
現在の `359-128-1193` は通常アカウントのため、API Centerを開いても空でした。

⚠️ **顧客IDはURLの `ocid=` ではありません。** `ocid` はGoogle内部の追跡番号で、
どちらも10桁のため見分けがつきません。正しい顧客IDは
画面右上のアカウント表示か、アカウント作成メールの「お客様 ID」で確認します。

残作業: MCCから既存アカウント `359-128-1193` へ**リンク申請 → 承認**（未実施）。

### 4-2. 開発者トークンを申請

1. MCCにログイン → ツールと設定 → 設定 → **API Center**
2. 申請フォームに記入
   - 用途：自社が運営するレンタルスペースの予約実績を、自社の広告アカウントへ
     オフラインコンバージョンとして取り込むため
   - 対象：自社アカウントのみ（第三者への提供なし）
3. 発行直後は **テストアクセス**（本番アカウントには使えない）
4. **Basic Access を申請**する（アクセスレベル横の▼から）

> ⚠️ 2026年時点で審査は混雑しており、**数日〜数週間**かかります。
> また申請元MCC配下のアカウントに対して**広告主確認**が求められる場合があります。
> その間は手順3のCSV運用を続けてください。

### 4-3. OAuth認証情報を作る

1. Google Cloud Console で新規プロジェクト
2. **Google Ads API** を有効化
3. OAuth同意画面を設定（内部／テストユーザーに自分を追加）
4. 認証情報 → OAuthクライアントID（**デスクトップアプリ**）を作成
5. クライアントIDとシークレットを控える
6. リフレッシュトークンを取得（スコープ `https://www.googleapis.com/auth/adwords`）

### 4-4. 環境変数を設定

`.env.local`（およびVercelの環境変数）に設定します。**キー名だけをコードに書き、値は絶対に書きません。**

```
GOOGLE_ADS_DEVELOPER_TOKEN=
GOOGLE_ADS_CLIENT_ID=
GOOGLE_ADS_CLIENT_SECRET=
GOOGLE_ADS_REFRESH_TOKEN=
GOOGLE_ADS_CUSTOMER_ID=          # 3591281193（ハイフンなし）
GOOGLE_ADS_LOGIN_CUSTOMER_ID=    # MCCのID（ハイフンなし・8476501294）
GOOGLE_ADS_CONVERSION_ACTION_ID= # 手順2で控えた数値ID
GOOGLE_ADS_API_VERSION=          # 未設定なら v25
```

> ⚠️ **APIバージョンは放置すると必ず壊れます。**
> 各バージョンは約1年で完全終了（sunset）し、終了後は全リクエストが失敗します。
> [終了予定日の一覧](https://developers.google.com/google-ads/api/docs/sunset-dates) を年1回確認し、
> `GOOGLE_ADS_API_VERSION` を書き換えてください（コード変更もデプロイも不要）。

設定が揃うと `/api/cron/google-ads-sync` が毎日 JST 7:00 に自動送信を始めます。
**揃うまでは自動でスキップされる**ので、先に環境変数だけ空で置いても問題ありません。

## 動作確認

### 計測が動いているかの確認

```sql
-- 広告経由の予約が記録されているか
select id, created_at, gclid, utm_source, utm_campaign, total_amount, conversion_exported_at
  from bookings
 where gclid is not null
 order by created_at desc
 limit 20;

-- 送信待ちの件数
select count(*) from google_ads_conversions;
```

### テスト方法

自分の広告を実際にクリックして予約すると `gclid` が付きます。
広告費が発生するので、**確認だけなら手動でURLに付けてもテストできます。**

```
https://（サイトURL）/kanda?gclid=TEST_MANUAL_001&utm_source=test
```

この状態で予約すると `bookings.gclid = 'TEST_MANUAL_001'` が入ります。
ただし**架空のgclidはGoogle Adsに取り込まれません**（実在するクリックIDではないため）。
DBに記録されるところまでの確認用です。

## 注意点

- **価格改定を先に済ませてから広告を向けてください。** 現在の価格のまま広告を流すと、
  育てたキーワードで安い価格に着地させることになります。
- コンバージョンが貯まるまで**2〜4週間は予算を増やさない**でください。
  目標が壊れた状態で予算を足すと、経路検索を買い増すだけになります。
- `gclid` は個人情報ではありませんが、予約と紐づくため
  他の予約者情報と同じ扱いで保護します（RLSは `bookings` に準拠）。
