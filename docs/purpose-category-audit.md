# 用途データ棚卸し・7分類実装の監査結果

作成: 2026-08-30 / 対象: Blue Space本番データベース(Supabaseプロジェクト`bluestage-booking`)
関連: `docs/media-disclosure-strategy.md` 付録B・5章、`docs/media-content-kit.md` 1章
実施内容: 実行フェーズ②「用途7分類の仕分けルールに沿った初回データの棚卸し」への対応。実データを直接確認し、7分類マッピングを実装した上で、公開に耐えるかを判定する。

## 0. 結論

- **用途カテゴリ(7分類・件数ベース)は、丸めた形であれば公開可能。** 外部モール(インスタベース/スペースマーケット/UPNOW)の`purpose`は想定と異なり**自由記述ではなく各モールの選択式ドロップダウン値**で、固有名詞やPIIは含まれていなかった(1章)。自社サイトの`purpose`は自由記述だが、実データを確認した範囲では固有名詞は含まれていなかった(2章)。ただし自由記述である以上、**月次公開前に毎回目視確認する運用は必須**とする。
- **稼働率(%)は今回の初回レポートには含めない。** 自動収集基盤(`occupancy_daily_snapshots`)が2026年7月19日に稼働開始したばかりで、前月比較に使える2ヶ月分のデータがまだ存在しない(3章)。
- **外部モールCSVの取込みには実務上のタイムラグがある。** 最新の取込みは2026年7月25日で、スペースマーケットは6月28日分まで、インスタベースは7月18日分までしか反映されていない(4章)。**執筆直前の月は「確定」として扱えない。** 今回集計に使える直近の完全な月は2026年6月。
- **付録Bの7分類には、実データに一定量存在する「作業・テレワーク・デスクワーク」(単独作業利用)の受け皿がない。** 今回はその他・未分類に含めたが、次回改訂時に8分類目としての追加を検討する余地がある(5章)。
- **拠点によって件数の桁が大きく異なる。** 特に京成小岩は対象期間(5-6月)の外部モール予約が実質ゼロで、自社サイトの予約も月0-1件と極めて少ない。単独の拠点別・月次比較には向かない(6章)。

## 1. `bookings.purpose`と`external_bookings.purpose`の性質の違い(想定との齟齬)

戦略書は当初、`bookings.purpose`・`external_bookings.purpose`のいずれも「自由記述」と想定していたが、実データを確認したところ以下の違いがあった。

| テーブル | 実際の性質 | 実データ例 |
|---|---|---|
| `bookings`(自社サイト) | 自由記述(想定通り) | 「会議」「ダンス」「説明会」「演技ワークショップ（12〜13名）」等。固有名詞は確認できなかった |
| `external_bookings`(外部モール) | **各モールの予約フォームの選択式ドロップダウン値**(自由記述ではない) | 「会議・打ち合わせ」「勉強会・セミナー」「ダンス」「作業」「テレワーク」等、約35種の定型値のみ。固有名詞は一切含まれない |

外部モール側が既にカテゴリ的な定型値である点は、7分類への丸め込みが想定より安全かつ機械的に行えることを意味する。一方、自社サイト側は自由記述のままであるため、**固有名詞混入のリスクは自社サイト経由の予約に限定される**(6章の運用ルール参照)。

## 2. 実データの内容確認(プライバシー観点)

2026年5-6月の confirmed 予約(自社+外部モール、300件超)の`purpose`値を確認した。

- 外部モールの値はすべて定型カテゴリ値(前述)で、固有名詞・個人名・企業名は含まれない。
- 自社サイトの自由記述(実件数は少数)も、確認できた範囲では「会議」「ダンス」「説明会」等の一般的な語句のみで、固有名詞・具体的な団体名・個人名は含まれていなかった。ただし件数が少ないため、**将来的な混入がないとは言い切れない**。

**結論**: 現時点のデータであれば、7分類に丸めた件数を公開しても、統計加工前の原文を経由した固有名詞流出リスクは低い。ただし自由記述フィールドである以上、**月次公開前に該当月の自社サイト分の`purpose`原文を必ず目視確認する運用を、恒久ルールとして`docs/media-content-kit.md` 1章の運用フローに追加する**(実施済み、本セッションで反映)。

## 3. 稼働率(%)データの成熟度

`occupancy_daily_snapshots`(cronによる稼働率の自動日次スナップショット)を確認したところ、データ範囲は**2026-07-19 〜 2026-08-29**のみだった。前月比較に必要な「連続する2つの完全な暦月」がまだ存在しない。

**判定**: 今回の初回レポートでは稼働率(%)の掲載を見送る。データが2ヶ月分の完全な暦月をカバーした時点(早くとも2026年9月末以降、10月分作成時)で掲載を再検討する。それまでは1章の運用フローに「稼働率は次回以降掲載」という位置づけを明記する。

## 4. 外部モールCSV取込みの現状(鮮度の確認)

| チャネル | 最終取込み日時 | 実データが反映されている最終日 |
|---|---|---|
| インスタベース | 2026-07-25 | 2026-07-18分まで |
| スペースマーケット | 2026-07-25 | 2026-06-28分まで |
| UPNOW | 2026-07-25 | 2026-07-11分まで |

3チャネルとも約1ヶ月前の同日に一括取込みされているが、各チャネルの反映範囲にはばらつきがある。**2026年7月分は、いずれのチャネルも月末まで反映されておらず「確定」として扱えない。** `docs/media-content-kit.md`が既に警告している「公開月の前月分CSVが最新化されていることを執筆前に必ず確認する」というルールが、まさに今回該当した形になる。

**今回の対応**: 初回ドラフト(`docs/note-report-2026-08-draft.md`)は、確実に完全なデータが揃っている**2026年6月度(2026年5月度との比較)**を対象に作成した。カレンダー上の本来の初回公開想定(2026年9月上旬・8月度)とは異なるため、**実際に公開する際は、8月分のCSVを再取込みした上で数値を差し替える**必要がある。

## 5. 7分類のカバレッジ確認

2026年6月度(confirmed、自社+外部モール計約190件)の`purpose`を7分類にマッピングした結果、以下のようになった(実装: `src/lib/purpose-category.ts`)。

| カテゴリ | 該当した主な実データ値 | 概算比率 |
|---|---|---|
| 会議・打ち合わせ | 会議・打ち合わせ、会議・商談、面接・面談 | 約2割 |
| セミナー・勉強会 | 勉強会・セミナー、セミナー・研修、研修 | 約1割 |
| レッスン・教室 | ダンス、稽古、ワークショップ、その他のレッスン・講座、演劇・芝居等 | 約15% |
| パーティー・懇親会 / 撮影・収録 / ボードゲーム会 | (各件数僅少のため、その他・未分類に統合) | — |
| その他・未分類 | その他、作業、テレワーク、デスクワーク、purpose未入力(モール側で約4分の1が未入力) | 約5割 |

**課題**: その他・未分類が約5割と大きい。内訳を見ると、(a)モール側でそもそも`purpose`が未入力のケースが多い(全体の1/4程度)、(b)「作業・テレワーク・デスクワーク」という単独作業利用が付録Bの7分類のどれにも当てはまらない、の2つが主因。無理な按分は行わず、方針どおりその他・未分類にまとめた。

**改善提案(今回は反映せず、次回検討事項として記録)**: 付録Bの7分類に「個人利用・テレワーク」を8分類目として追加することを、次回の戦略書改訂時にオーナーへ提案する。

## 6. 拠点別の件数の偏り

2026年5-6月の外部モール確定件数(拠点別):

- ブルースペース上野御徒町: 64件→38件
- ブルースペース上野駅前4A: 19件→35件
- ブルースペース上野駅前4B: 38件→39件
- ブルースペース神田: 23件→30件
- ブルースペース西新宿403: 30件→32件
- ブルースペース白金高輪: 14件→15件
- **ブルースペース京成小岩: 対象期間中0件(外部モール)。自社サイト経由も月0〜1件のみ**

**判定**: 京成小岩は対象期間の予約数が極めて少なく、単独で月次の前月比・稼働率を出すと「ほぼ稼働していない拠点」という印象を過度に強めるか、逆に少数事例(1〜2件)が特定されるリスクがある。**初回レポートでは京成小岩を含む7拠点合計値・全社の用途カテゴリは掲載するが、拠点別ハイライト表では京成小岩のみ「件数僅少のため今回は前月比の掲載を見送り」と注記する。**

また、自社サイト経由の予約には、上野御徒町で同一の「演技ワークショップ」が数ヶ月にわたり毎週予約されているケースを確認した(2026年6月以降、少なくとも2027年2月まで継続予約あり)。これは特定の1組織・1講師による継続利用とみられ、**特定の月だけを見ると「上野御徒町はワークショップ利用が突出して多い」という形で、件数の集中それ自体が特定の利用者を推測させ得る。** 用途カテゴリは7分類に丸めているため個別の団体名等は出ないが、**同一カテゴリが特定拠点で継続的に高い比率を占める場合は、月ごとの比率のブレを均すか、「継続利用が多い」という定性的な表現に留め、正確な比率の露出を避ける**運用とする。

| 項目 | 判定 | 備考 |
